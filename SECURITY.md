# Security policy

`oss-client` is a game client. The interesting question for a client is not what
a player can do to a server — it is **what a server can do to the player who
connected to it**.

A zone is a stranger's machine. You type its address, and from that moment it
sends you settings, a map, archives of graphics and sounds, and a stream of
packets, and this client parses all of it. A malicious zone is a realistic
threat, not a theoretical one: zone addresses get passed around, and nobody
audits a server before joining it.

**That is the exposure this policy is most interested in.**

## Reporting a vulnerability

**Use GitHub's private reporting, not a public issue.**

> **Security → Report a vulnerability**, or go straight to
> <https://github.com/DangerMouseUK/oss-client/security/advisories/new>

That opens a private thread with the maintainer. Nothing in it is visible to
anyone else unless and until an advisory is published.

**If you are not sure whether what you found is a security problem, report it
privately anyway.** Deciding that is our job. A private report that turns out to
be an ordinary bug costs nothing; a public issue that turns out to be a real
vulnerability cannot be taken back.

## Which version

There are no releases and no tags yet, so there is no version table here and it
would be dishonest to invent one. **`main` is the only version there is.** When
you report something, say which commit you were on — `git rev-parse HEAD`.

## In scope

**What a hostile or compromised server can do to a connected player**, first and
foremost:

- **Crashing or hanging the client** with a crafted packet, settings block, map
  or archive. Untrusted data is never supposed to panic the client.
- **A map or `.lvz` download that does something other than describe a map** —
  unbounded allocation, a decompression bomb, work disproportionate to its size.
- **Anything that writes outside the directory it is supposed to write in.**
  Downloaded content arrives with names chosen by the server, so a path that
  escapes its directory is exactly the kind of thing worth looking for.
- **Anything that gets code or a file onto the player's machine**, or that makes
  the client execute, load or run something the player did not choose.
- **Anything that leaks the player's data to the zone** beyond what playing
  requires — credentials, local paths, files, or details of their machine.

Also in scope:

- **Credential handling**: how a password is held in memory, what reaches a log
  or a crash dump, and what is written to disk.
- **Loading assets and files from local disk**, including from a Continuum
  install the client was pointed at.

## Out of scope

- **Cheating.** Modifying your own client to gain an advantage is a matter for
  the server you are playing on, not a vulnerability in this one. Please do not
  send cheat techniques through the security channel.
- **Zones that other people run.** If a zone is behaving badly, that belongs to
  whoever runs it. What belongs here is a zone being *able* to hurt the client.
- **The bundled graphics and sounds in `assets/classic/`.** They are not this
  project's work and are not covered by this policy; see
  [`assets/classic/README.md`](assets/classic/README.md). A parsing bug in the
  code that *reads* them is in scope — the files themselves are not.
- **Reports generated by a scanner with no analysis attached.** Tell us what an
  attacker would actually be able to do.

## What to expect

This is a volunteer project with one maintainer, and replies will not be
instant.

- **Acknowledgement within seven days.** If you have heard nothing after that,
  the message went astray rather than being ignored — please ping the thread.
- We will tell you whether we think it is a real vulnerability, and why.
- If it is, we will fix it on `main` and publish an advisory. **You will be
  credited by whatever name you ask for, or not at all if you prefer.**
- We will not ask you to sit on something indefinitely. If we go quiet or cannot
  fix it, publishing is your call.

**There is no bug bounty**, and there is no funding to start one.

## One thing this policy is not for

This file is about **vulnerabilities in this code**. It is not a channel for
questions about what the project does or does not implement, or why. Those
belong in an ordinary issue.

Much of what this client parses is implemented in the shared crates. If the bug
is in packet decoding, the transport layer or a map file, it may belong in
[oss-core](https://github.com/DangerMouseUK/oss-core) — report it wherever you
found it and we will move it if needed. **Do not let uncertainty about which
repository it belongs in stop you reporting it.**
